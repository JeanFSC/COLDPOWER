# CP-031 — Contratos de Dashboard y Catálogo administrativo

CP-031 agrega lógica de lectura y mutación real para Dashboard y Productos sin
renombrar los campos que ya consume la interfaz administrativa.

## Dashboard

`GET /api/admin/dashboard` requiere `dashboard.view` y acepta:

`range`, `from`, `to`, `locationId`, `sellerId`, `customerId`, `productId`,
`categoryId`, `familyId`, `brandId`, `channel` y `orderStatus`.

Los rangos válidos son `today`, `yesterday`, `week`, `month` y `custom`. Las
fechas usan `YYYY-MM-DD` y las ventanas se resuelven en `America/Lima`.

Se mantienen sin cambios estos campos: `salesToday`, `salesMonth`,
`salesRange`, `orders`, `quotes`, `opportunities`, `pipelineValue`,
`criticalStock`, `noStock`, `unknownStock`, `noMovement`, `conversion`,
`newCustomers`, `returningCustomers`, `productsSold`, `unitsSold`, `margin`,
`overdueFollowUps`, `topProducts`, `topCustomers`, `topSellers`, `channels`,
`salesSeries`, `previousSalesSeries`, `pipelineSummary`, `userSummary` y
`recentActivity`.

Se agregan de forma aditiva:

- Financieros: `sales`, `revenue`, `costOfSales`, `grossProfit`, `grossMargin`,
  `operatingExpenses`, `operatingProfit` y `profitability`.
- Resúmenes: `categorySummary`, `pendingPaymentsCount`,
  `criticalStockCount`, `overdueFollowUpsCount`, `pendingQuotesCount` y
  `pendingApprovalsCount`.
- Etiquetas: `stageCode`/`stageLabel`, `roleCode`/`roleLabel`,
  `statusCode`/`statusLabel`, `actionLabel`, `entityLabel` y `actorName`.
- Cada punto de `salesSeries` puede incluir `orders` y `units`, sin quitar
  `date`, `total` ni `count`.

Los días sin ventas aparecen con cero en las series. `unknownStock` representa
productos sin balance de inventario y no se convierte en stock cero. Costos,
márgenes y rentabilidad se devuelven como `null` si falta una fuente necesaria
o si el actor no posee `pricing.cost.view` y `pricing.margin.view`.

`GET /api/admin/dashboard/export` reutiliza exactamente los mismos filtros y
permisos, devuelve CSV UTF-8 con BOM y omite columnas financieras cuando el
actor no puede verlas. Un alcance válido sin datos exportables responde
`DASHBOARD_EMPTY` con HTTP 404.

Ejemplo reducido:

```json
{
  "sales": 0,
  "revenue": 0,
  "unknownStock": 1348,
  "salesSeries": [{ "date": "2026-08-14", "total": 0, "count": 0 }],
  "previousSalesSeries": [{ "date": "2026-08-13", "total": 0, "count": 0 }],
  "pipelineSummary": [],
  "userSummary": [],
  "recentActivity": []
}
```

## Catálogo administrativo

`GET /api/admin/catalogo` requiere `catalog.product.view` y acepta búsqueda,
SKU, nombre, categoría/familia/marca por slug o ID, `publicationStatus`,
`requiresReview`, `possibleDuplicate`, `confidence`, `sourceStatus`, `page` y
`pageSize` (máximo 100).

La respuesta devuelve `{ items, page, pageSize, totalItems, totalPages,
queues, facets }` y conserva aliases temporales `{ rows, total }` para la
interfaz existente. La paginación ocurre en PostgreSQL, no sobre la página ya
cargada.

Cada fila conserva la identidad importada (`sku`, `originalName`,
`normalizedName`, `sourceStatus`, `sourcePage`, `sourceRow`) y agrega estado de
publicación, revisión, duplicado, `stock` y `media`. El stock usa únicamente:
`AVAILABLE`, `LOW`, `ZERO` y `UNKNOWN`.

Las colas son globales y no cambian al filtrar la tabla: productos totales,
publicados, borradores, ocultos, en revisión, duplicados, pendientes de
revisión, marcas y categorías. Las facetas salen de la base de datos activa.

Ejemplo reducido:

```json
{
  "items": [{
    "sku": "CP-001",
    "publicationStatus": "review",
    "publicationStatusLabel": "En revisión",
    "stock": { "state": "UNKNOWN", "onHand": null, "reserved": null, "available": null },
    "media": null
  }],
  "page": 1,
  "pageSize": 12,
  "totalItems": 1348,
  "totalPages": 113,
  "queues": { "totalProducts": 1348, "reviewProducts": 1348 },
  "facets": { "categories": [], "families": [], "brands": [] }
}
```

`POST /api/admin/catalogo` requiere `catalog.product.create`. Crea productos
manuales como `MANUAL` y `draft`, valida SKU y taxonomía, no permite enviar
identidad importada y escribe auditoría `PRODUCT_CREATED`.

`GET /api/admin/catalogo/:id` requiere `catalog.product.view` y devuelve
`sourceIdentity`, `editorialData`, `taxonomy`, `publication`,
`duplicateInformation`, `stockSummary`, `media`, `pricing`, `priceHistory` y
`auditHistory`. Los precios quedan en `null` para actores sin permisos de
costos y margen.

`PATCH /api/admin/catalogo/:id` requiere `catalog.product.edit` y sólo permite
campos editoriales: nombre comercial, descripción, destacado y taxonomía
editorial. La identidad fuente es de solo lectura.

`PATCH /api/admin/catalogo/:id/publication` requiere
`catalog.product.publish`. Las transiciones válidas son:

`draft -> review`, `review -> published`, `review -> draft`,
`published -> hidden` y `hidden -> published`.

`PATCH /api/admin/catalogo/:id/duplicate` requiere
`catalog.product.review`; rechaza canónicos propios y canónicos fuera del
grupo de duplicados. `POST`/`DELETE /api/admin/catalogo/:id/media` requieren
`catalog.product.edit`, validan media activa y auditan asociación/remoción.

## Errores y estado actual de QA local

Los endpoints usan `{ error: { code, message, details } }`. Códigos CP-031:

`DASHBOARD_INVALID_FILTER`, `DASHBOARD_FORBIDDEN`, `DASHBOARD_EMPTY`,
`DASHBOARD_UNAVAILABLE`, `CATALOG_INVALID_FILTER`, `CATALOG_VALIDATION_ERROR`,
`CATALOG_FORBIDDEN`, `CATALOG_PRODUCT_NOT_FOUND`, `CATALOG_PUBLICATION_INVALID`,
`CATALOG_DUPLICATE_INVALID`, `CATALOG_MEDIA_INVALID`,
`CATALOG_MEDIA_NOT_FOUND` y `CATALOG_UNAVAILABLE`.

En la base local verificada hay 1.348 productos importados, 27 categorías,
171 familias y 60 marcas. Actualmente los productos están en revisión, no hay
ventas confirmadas y el inventario no tiene balances para esos productos; por
eso el catálogo público no muestra productos publicados y `unknownStock` es
1.348. Estos son datos actuales de QA, no valores simulados ni hardcodeados.
